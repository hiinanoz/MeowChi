# Meowchi — Architecture & Roadmap

## Platform decisions

| Topic | Decision | Why |
|---|---|---|
| Minimum iOS | **17.0** | SwiftData, `@Observable` and String Catalogs all need iOS 17. iOS 17+ covers the vast majority of active iPhones. |
| Devices | iPhone first (all sizes, portrait). iPad = Phase 7 (`TARGETED_DEVICE_FAMILY` in `project.yml`). | One layout to perfect first. The scene already scales by whole-number factors, so iPad mostly needs HUD layout work. |
| Toolchain | Builds with Xcode 15.2 (local Mac, macOS 13). Code avoids iOS 18-only APIs and Swift 6 features. | The dev Mac can't run newer Xcode. **App Store uploads need a newer SDK** → release builds go through GitHub Actions (Xcode 26) (see Risks). |
| Dependencies | None. SwiftUI + SpriteKit + SwiftData + AVFoundation. | Offline, no account needed, nothing to maintain. |
| Project file | Generated by XcodeGen from `project.yml` (not committed). | Adding a file = drop it in a folder and regenerate. No pbxproj merge conflicts. |

## Architecture

```
SwiftUI (Features/)  ──reads──▶  GameStore (@Observable, @MainActor)  ──▶  SaveStore (SwiftData)
      │                              │  validates & applies every action
      │ SpriteView                   │  calls CatSimulator (pure functions)
      ▼                              ▼
RoomScene (SpriteKit)  ──calls──▶ store.pet() / reads store.mood
```

- **GameState** (`Models/`): one Codable value type holding everything that's saved. Easy to test.
- **GameStore** (`Game/`): the only thing that changes state. Actions return an `ActionResult`
  (`.ok`, `.busy`, `.outOfStock`…). State changes and the save happen **before** the animation,
  so an interrupted animation can never use up an item twice.
- **CatSimulator** (`Game/Simulation/`): pure, deterministic, elapsed-time simulation. No timers.
- **RoomScene / CatNode** (`Game/`): rendering only. Fixed 360×400 logical room (1 art px = 1 pt), whole-number scale,
  nearest-neighbor filtering, the sprite snaps to whole pixels every frame.
- **Persistence**: SwiftData `SaveRecord` holding a versioned JSON envelope (`SaveCodec`), plus the
  previous good payload as a backup. Unreadable saves are quarantined and the player is told. Progress is never silently reset.
- **Balance** (`Core/Balance.swift`): all tuning numbers in one place. Item values sit in `ItemCatalog`.

## Simulation rules (v1)

Applied in 15-minute steps from `lastSimulatedAt` to now:

- Awake: hunger −6/h, energy −5/h. Asleep: hunger −3/h, energy +30/h, auto-wake at 100.
- Cleanliness −3/h. Happiness −2/h, plus −3/h more while any need is below 30.
- Health −1.5/h while hunger or cleanliness is below 25, otherwise +1/h.
- **Fairness:** time alone can't push a need below 10 or health below 30. Offline time is capped at 24 h. No death.
- **Clock safety:** if the clock goes backwards, no change; only the reference time is reset. Bad numbers are repaired by clamping.
- Petting: +4 happiness, 1.5 s cooldown, max 12 rewarded pets per hour (it still reacts after that, but gives no reward).

## Risks & dependencies

1. **App Store SDK requirement (high).** Xcode 15.2 can build and test locally, but App Store Connect only accepts builds made with a recent SDK. Fix: GitHub Actions on macos-15 with Xcode 26 (`release.yml`). Plan this before Phase 6.
2. **Art (high).** The current sprites are code-generated placeholders. Final art must follow `docs/ASSETS.md` and keep the same asset names.
3. **Font.** A system monospaced font for now, so Japanese and Korean text work. A pixel font needs a license and CJK fallback.
4. **SwiftData on iOS 17.0–17.x** has known quirks. That's why the whole state is saved as one JSON payload, so it doesn't depend on complex relationships.
5. **Bundle ID** is `com.othinks.Meowchi` (same pattern as `com.catgridcollection.nonogram`). Register it in the Developer portal before the first upload; it can't change after the App Store record exists.
